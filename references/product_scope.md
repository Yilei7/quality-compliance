# 产品边界与候选版声明

## 当前定位

`quality-compliance-core 0.1.0-rc.1` 是供受控试点使用的技术候选版，不是可直接公开销售或部署给不受支持客户的正式产品。它可以独立执行领域工作流，但不作出最终法律或合规结论，也不能替代企业质量负责人、法规人员或外部合格审核人员。

## 当前纳入范围

- 地域与主体：上海市医疗器械经营企业（`device_distribution`）。
- 数据模型：每个运行数据目录对应一家企业。
- 工作流：初始建档、基线诊断、基线确认、常规巡检、证据关联。
- 辅助材料：迎检自查清单和缺陷整改/CAPA 草案框架。
- 集成方式：Python 3.10 及以上环境中的单请求 JSON 标准输入/输出接口。

## 当前未纳入范围

- 药品经营或生产、医疗器械生产，以及上海市以外属地规则。
- 向监管部门自动申报、监管账号自动登录或第三方系统直连。
- 多企业租户、用户注册登录、权限、计费、云同步和远程升级。
- 电子签名、不可篡改审计追踪、法定档案保管或灾难恢复承诺。
- 对法规适用性、企业是否合规或能否通过检查作最终判定。
- 自动跟踪官方法规变化，或保证内置监管内容始终为最新版本。

## 监管内容状态

包内任务库的状态是 `draft-requires-qualified-review`。任务和巡检输出中的 `source_status` 必须保留并展示；在合格审核人员完成逐项核验、登记现行官方来源和审核日期前，不得改称“已验证”“官方认可”或“保证合规”。

## 数据与人员责任

- 企业资料和证据仅写入包外运行目录；分发包中不得包含客户数据。
- 部署方负责运行目录的访问控制、备份、保留期限和安全删除。
- 质量负责人负责确认企业事实、证据真实性、任务完成状态和整改关闭。
- 对外提供服务前，经营方仍需完成隐私、安全、许可协议、支持和事件响应设计。

## 正式发布门槛

以下事项全部完成后，才能把 `public_release_ready` 改为 `true`：

1. 合格审核人员逐项核验监管内容，补齐官方来源登记和审核日期。
2. 完成隐私与安全评审，并定义备份、访问控制和事件响应流程。
3. 确定代码、内容和客户数据的许可及使用条款。
4. 明确支持范围、升级兼容策略和问题召回机制。
5. 若作为联网产品提供，另行完成身份认证、多租户隔离、日志和计费设计。
